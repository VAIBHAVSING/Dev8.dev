## Overview

Dev8.dev uses multiple types of Azure credentials for different purposes. This guide explains how to manage them securely.

### Security Principles

1. **Never commit credentials to git**
2. **Use least-privilege access**
3. **Rotate credentials regularly**
4. **Store credentials securely**
5. **Monitor credential usage**

## Credential Types

### 1. Service Principal

**Purpose:** Programmatic access to Azure resources from Go backend

**Components:**
- Client ID (Application ID)
- Client Secret (Password)
- Tenant ID
- Subscription ID

**Location:**
- `azure-credentials.json` (generated by setup script)
- `.env.azure` (environment variables)
- `apps/agent/.env` (Go backend)

**Permissions:**
- Contributor role on `dev8-mvp-rg` resource group

### 2. Storage Account Credentials

**Purpose:** Access Azure Files for workspace persistence

**Components:**
- Storage Account Name
- Storage Account Key
- Connection String

**Location:**
- `.env.azure`
- `apps/agent/.env`

**Permissions:**
- Full access to storage account

### 3. Container Registry Credentials

**Purpose:** Push/pull Docker images for VS Code environments

**Components:**
- Registry Name
- Admin Username
- Admin Password
- Login Server URL

**Location:**
- `.env.azure`
- `apps/agent/.env`

**Permissions:**
- Admin access to container registry (MVP)
- AcrPush/AcrPull roles (Production)

### 4. Personal Azure Account

**Purpose:** Administrative access via Azure Portal and CLI

**Components:**
- Email address
- Password
- MFA code

**Permissions:**
- Contributor or Owner on subscription

## Setup and Configuration

### Initial Setup

Run the automated setup script:

```bash
cd scripts/azure
./setup-infrastructure.sh
```

This creates:
- `azure-credentials.json` - Service principal credentials
- `.env.azure` - Root level environment variables
- `apps/agent/.env` - Go backend environment variables

### Manual Setup

If you need to create credentials manually:

#### 1. Create Service Principal

```bash
# Get subscription ID
SUBSCRIPTION_ID=$(az account show --query id -o tsv)
RESOURCE_GROUP="dev8-mvp-rg"

# Create service principal
az ad sp create-for-rbac \
  --name dev8-mvp-sp \
  --role Contributor \
  --scopes /subscriptions/$SUBSCRIPTION_ID/resourceGroups/$RESOURCE_GROUP \
  --sdk-auth > azure-credentials.json

# Secure the file
chmod 600 azure-credentials.json
```

**azure-credentials.json format:**
```json
{
  "clientId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "clientSecret": "your-client-secret-here",
  "subscriptionId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "tenantId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "activeDirectoryEndpointUrl": "https://login.microsoftonline.com",
  "resourceManagerEndpointUrl": "https://management.azure.com/",
  "activeDirectoryGraphResourceId": "https://graph.windows.net/",
  "sqlManagementEndpointUrl": "https://management.core.windows.net:8443/",
  "galleryEndpointUrl": "https://gallery.azure.com/",
  "managementEndpointUrl": "https://management.core.windows.net/"
}
```

#### 2. Get Storage Credentials

```bash
STORAGE_NAME="dev8mvpstorage12345678"
RESOURCE_GROUP="dev8-mvp-rg"

# Get storage key
STORAGE_KEY=$(az storage account keys list \
  --resource-group $RESOURCE_GROUP \
  --account-name $STORAGE_NAME \
  --query "[0].value" -o tsv)

# Get connection string
CONNECTION_STRING=$(az storage account show-connection-string \
  --name $STORAGE_NAME \
  --resource-group $RESOURCE_GROUP \
  --query connectionString -o tsv)

echo "AZURE_STORAGE_KEY=$STORAGE_KEY"
echo "AZURE_STORAGE_CONNECTION_STRING=$CONNECTION_STRING"
```

#### 3. Get Registry Credentials

```bash
REGISTRY_NAME="dev8mvpregistry12345678"

# Get registry credentials
az acr credential show \
  --name $REGISTRY_NAME \
  --query "{username:username, password:passwords[0].value}"

# Get login server
az acr show \
  --name $REGISTRY_NAME \
  --query loginServer -o tsv
```

## Storage Best Practices

### File System Security

**Set proper permissions:**
```bash
# Restrict access to owner only (read/write)
chmod 600 .env.azure
chmod 600 apps/agent/.env
chmod 600 azure-credentials.json

# Verify
ls -la .env.azure
# Expected: -rw------- (600)
```

**Never:**
- Commit to git (use .gitignore)
- Share via email or chat
- Store in cloud storage (Dropbox, Google Drive)
- Include in Docker images

### Git Protection

**Verify .gitignore:**
```bash
# Check .gitignore includes sensitive files
cat .gitignore | grep -E '\.env|azure-credentials'

# Should see:
# .env
# .env.azure
# azure-credentials.json
```

**Test git status:**
```bash
git status

# Sensitive files should NOT appear in:
# - Changes to be committed
# - Untracked files
```

**Remove accidentally committed credentials:**
```bash
# If you accidentally committed
git rm --cached .env.azure
git rm --cached azure-credentials.json

# Add to .gitignore
echo ".env.azure" >> .gitignore
echo "azure-credentials.json" >> .gitignore

# Commit
git commit -m "Remove sensitive files"
git push

# IMPORTANT: Rotate all exposed credentials immediately!
```

### Backup Strategy

**Secure backup location:**
```bash
# Encrypt and backup (do NOT store in git)
tar czf azure-credentials-backup.tar.gz \
  .env.azure \
  azure-credentials.json \
  apps/agent/.env

# Encrypt with GPG
gpg --symmetric --cipher-algo AES256 azure-credentials-backup.tar.gz

# Store encrypted file securely
# Delete unencrypted backup
rm azure-credentials-backup.tar.gz
```

**Recovery process:**
```bash
# Decrypt
gpg --decrypt azure-credentials-backup.tar.gz.gpg > azure-credentials-backup.tar.gz

# Extract
tar xzf azure-credentials-backup.tar.gz

# Restore files
# Verify and delete backup
rm azure-credentials-backup.tar.gz
```

## Using Credentials

### In Go Backend

```go
package main

import (
    "os"
    "github.com/joho/godotenv"
    "github.com/Azure/azure-sdk-for-go/sdk/azidentity"
)

func main() {
    // Load environment variables
    godotenv.Load()
    
    // Create credential
    cred, err := azidentity.NewClientSecretCredential(
        os.Getenv("AZURE_TENANT_ID"),
        os.Getenv("AZURE_CLIENT_ID"),
        os.Getenv("AZURE_CLIENT_SECRET"),
        nil,
    )
    if err != nil {
        panic(err)
    }
    
    // Use credential with Azure SDK clients
    // ...
}
```

### In Shell Scripts

```bash
#!/bin/bash

# Load environment variables
source .env.azure

# Use credentials
az login --service-principal \
  -u $AZURE_CLIENT_ID \
  -p $AZURE_CLIENT_SECRET \
  --tenant $AZURE_TENANT_ID

# Use with Azure SDK
az container create \
  --resource-group $AZURE_RESOURCE_GROUP \
  --name my-container \
  # ...
```

### In Docker (Development Only)

**⚠️ Never include real credentials in production Docker images**

For local development:
```dockerfile
# Development only - use docker secrets in production
ENV AZURE_CLIENT_ID=${AZURE_CLIENT_ID}
ENV AZURE_CLIENT_SECRET=${AZURE_CLIENT_SECRET}
```

Better approach:
```bash
# Pass as build args (local dev only)
docker build \
  --build-arg AZURE_CLIENT_ID=$AZURE_CLIENT_ID \
  --build-arg AZURE_CLIENT_SECRET=$AZURE_CLIENT_SECRET \
  -t myimage .

# Or mount as volume
docker run -v $(pwd)/.env.azure:/app/.env.azure myimage
```

### In CI/CD (GitHub Actions)

```yaml
name: Deploy

on: [push]

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Azure Login
        uses: azure/login@v1
        with:
          creds: ${{ secrets.AZURE_CREDENTIALS }}
      
      # AZURE_CREDENTIALS secret contains azure-credentials.json content
```

**Setting secrets in GitHub:**
1. Repository → Settings → Secrets
2. New repository secret
3. Name: `AZURE_CREDENTIALS`
4. Value: Contents of `azure-credentials.json`

## Rotation and Maintenance

### Service Principal Rotation

**Recommended frequency:** Every 90 days

```bash
# Reset service principal credentials
CLIENT_ID=$(cat azure-credentials.json | jq -r '.clientId')

az ad sp credential reset \
  --id $CLIENT_ID \
  --years 1 \
  --query "{clientId:appId, clientSecret:password}" \
  --output json > azure-credentials-new.json

# Update environment files with new secret
# Test new credentials
# Delete old credentials file
```

### Storage Key Rotation

**Recommended frequency:** Every 180 days

```bash
STORAGE_NAME="dev8mvpstorage12345678"
RESOURCE_GROUP="dev8-mvp-rg"

# Regenerate key2 (while key1 is still active)
az storage account keys renew \
  --resource-group $RESOURCE_GROUP \
  --account-name $STORAGE_NAME \
  --key key2

# Update applications to use key2
# Wait for all apps to switch

# Regenerate key1
az storage account keys renew \
  --resource-group $RESOURCE_GROUP \
  --account-name $STORAGE_NAME \
  --key key1

# Update environment files
```

### Registry Password Rotation

**Recommended frequency:** Every 90 days

```bash
REGISTRY_NAME="dev8mvpregistry12345678"

# Regenerate password2 (while password1 is active)
az acr credential renew \
  --name $REGISTRY_NAME \
  --password-name password2

# Update applications to use password2
# Regenerate password1
```

### Automated Rotation (Advanced)

```bash
#!/bin/bash
# rotate-credentials.sh

# Add to cron job to run monthly
# 0 0 1 * * /path/to/rotate-credentials.sh

# Rotate service principal
./scripts/azure/configure-credentials.sh

# Send notification
echo "Azure credentials rotated on $(date)" | mail -s "Credential Rotation" admin@dev8.dev
```

## Troubleshooting

### Invalid Credentials Error

```bash
ERROR: AADSTS7000215: Invalid client secret provided
```

**Solutions:**
1. Verify environment variables are loaded
2. Check for trailing spaces or quotes
3. Regenerate credentials
4. Ensure service principal not deleted

### Permission Denied Error

```bash
ERROR: The client does not have authorization
```

**Solutions:**
1. Check service principal role assignment
2. Verify resource group name
3. Ensure subscription is correct
4. Wait 5 minutes for permissions to propagate

### Expired Credentials

```bash
ERROR: AADSTS7000222: The provided client secret keys are expired
```

**Solution:**
```bash
# Reset immediately
az ad sp credential reset --id $CLIENT_ID
```

### Finding Credentials

**Locate service principal:**
```bash
# By display name
az ad sp list --display-name dev8-mvp-sp

# By client ID
az ad sp show --id $CLIENT_ID
```

**Get current storage key:**
```bash
az storage account keys list \
  --resource-group $RESOURCE_GROUP \
  --account-name $STORAGE_NAME
```

**Get current registry password:**
```bash
az acr credential show --name $REGISTRY_NAME
```

- [ ] Incident response plan in place
- [ ] Credentials monitored for unusual usage
